# Length Guidelines

지식 파일은 길이가 늘어나면 주제가 섞이고 AI 탐색 효율이 떨어진다. 아래 기준은 **권장 (강제 아님)** 이며 kb-validator 가 초과 시 사용자에게 분리 여부를 확인한다.

## 기준

| 유형 | 권장 최대 줄 수 | 비고 |
|------|----------------|------|
| 일반 지식 (가이드, 개념, 레퍼런스) | 1000 줄 | 기본값 |
| 시각화 / 다이어그램 / 대규모 표 포함 | 2000 줄 | 이미지/차트가 줄 수를 차지하는 경우 |
| 리서치 문서 | 2500 줄 | 연속된 서술 / 인용 / 데이터가 많음 |
| 리서치 문서 (강력 분할 권장) | 4000 줄 이상 | 이 기준 넘으면 거의 항상 분할 |
| 특별한 성격 (제약 사항, 글로서리 등) | 예외 허용 | `length-exempt` 태그 |

"줄 수" 는 공백/코드블럭/frontmatter 포함한 총 줄 수.

### 리서치 기준을 2500 줄로 두는 이유

- 1000 줄 기준은 가이드/개념 설명 기준이라 리서치에 너무 엄격
- 2500 줄이면 학술 논문 한 편 수준 (10~15페이지 PDF) 으로, 읽기 흐름이 유지되는 상한선
- 4000 줄 넘으면 독자/AI 둘 다 한 번에 파악이 어려워짐 → 분할이 거의 필수

## 초과 시 분리 기준

- 본문에 top-level 헤딩이 3개 이상이면 각각 별도 파일로 쪼갤 후보
- 한 섹션 안에 서로 독립된 주제가 섞여 있으면 쪼개기
- "Related" / "References" 같은 부록이 비대해지면 별도 index 파일로

## 리서치 문서 분할 패턴 (2500 줄 초과)

긴 리서치는 **서브디렉토리 + 번호 접두사** 패턴으로 분할한다.

```
research/{topic-name}.md              # 짧으면 단일 파일 (~2500 줄까지)
→
research/{topic-name}/                # 길면 서브디렉토리로
├── README.md                         # 요약 + TOC + 핵심 결론 (~200 줄)
├── 01-background.md                  # 배경, 용어, 선행 연구 (~800 줄)
├── 02-methodology.md                 # 실험 방법 / 접근법 (~900 줄)
├── 03-results.md                     # 결과 / 측정 (~900 줄)
├── 04-discussion.md                  # 고찰 / 시사점 (~700 줄)
├── 05-references.md                  # 인용 / 외부 링크 (~300 줄)
├── diagrams/
│   └── {name}.mermaid                # 다이어그램 소스 (frontmatter 불필요)
└── data/
    └── {name}.json                   # 원본 데이터 (frontmatter 불필요)
```

### 분할 규칙

1. 각 `.md` 하위 파일은 **1000 줄 미만** 유지
2. `README.md` 는 전체 요약 + TOC + 핵심 결론 (3~5줄) 을 담는 "착륙 페이지" 역할
3. 번호 접두사 (`01-`, `02-`) 로 읽기 순서 명시
4. 첨부 (다이어그램, 데이터) 는 서브디렉토리 (`diagrams/`, `data/`) 에 분리
5. 하위 파일 간 관계는 `relations` 로 명시 (README + 관련 섹션)

### 분할 결정 체크리스트

2500 줄을 넘겼을 때 아래 질문에 **2개 이상 Yes** 면 분할:

- Top-level 섹션이 4개 이상인가?
- 각 섹션이 독립적으로 읽혀도 의미 있는가?
- 첨부 데이터/다이어그램 파일이 있는가?
- 태그가 섹션마다 다르게 부여되는 게 자연스러운가?

### 분할 효과

- **AI 로드 비용**: 필요한 섹션만 로드 가능 (전체 로드 시 컨텍스트 포화 방지)
- **태그 검색 정밀도**: 단일 파일일 때보다 섹션 단위로 매칭
- **수정 충돌 감소**: 섹션별로 독립 커밋 가능
- **트레이드오프**: 연속적 서술이 끊기는 단점 → `README.md` 의 TOC 가 안내 역할

## 분리 전후 관계

- 분리된 새 파일들은 원본을 `relations` 에 유지
- 원본을 유지할 경우: 본문 상단에 "이 문서는 다음으로 분리되었습니다:" 섹션 추가
- 원본을 삭제하고 대체할 경우:
  - 원본을 deprecated 로 변경 후 일정 기간 유지 (참조 문서가 적응할 시간)
  - 또는 relations cleanup 을 거쳐 완전 삭제 (references/rule-relations.md 의 삭제 플로우)

## kb-validator 동작

- 필수 아님 (권장 항목)
- 초과 감지 시: 사용자에게 `"{path} 가 {N}줄입니다. 분리를 검토할까요?"` 확인
- "skip" 선택 시 해당 경고 이 세션에서 무시. 다음 실행 때 다시 감지

### 문서 유형별 임계값 판단

kb-validator 는 다음 기준으로 유형을 자동 판단:

- 경로에 `research/` 포함 → 리서치 임계값 (2500 / 4000) 적용
- 태그에 `visualization` / `diagram` / `mermaid` 포함 → 시각화 임계값 (2000) 적용
- 그 외 → 일반 임계값 (1000) 적용

잘못 판단되는 경우 `length-exempt` 태그로 해당 파일 제외.

## 예외

아래 경우 경고 자체를 비활성화할 수 있다. 파일 frontmatter 에 태그 추가:

```yaml
tags: [..., length-exempt]
```

예외 태그가 있는 파일은 kb-validator 가 길이 경고에서 제외. 대신 해당 태그가 있으면 kb-validator 가 한 번은 "정말 예외 맞는지" 확인 후 더 이상 묻지 않는다.

## 왜 하드 리밋이 아닌가

- 도메인에 따라 정상 크기가 다르다 (용어집은 자연스럽게 길어짐)
- 강제 분리는 오히려 문맥 단절을 만든다
- 권장 + 알림 방식이 팀 문화에 적응하기 쉽다
