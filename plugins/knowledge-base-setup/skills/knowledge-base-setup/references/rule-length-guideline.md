# Length Guidelines

지식 파일은 길이가 늘어나면 주제가 섞이고 AI 탐색 효율이 떨어진다. 아래 기준은 **권장 (강제 아님)** 이며 kb-validator 가 초과 시 사용자에게 분리 여부를 확인한다.

## 기준

| 유형 | 권장 최대 줄 수 |
|------|----------------|
| 일반 지식 | 1000 줄 |
| 시각화 / 다이어그램 / 대규모 표 포함 | 2000 줄 |
| 특별한 성격 (제약 사항, 글로서리 등) | 상황에 따라 예외 허용 |

"줄 수" 는 공백/코드블럭/frontmatter 포함한 총 줄 수.

## 초과 시 분리 기준

- 본문에 top-level 헤딩이 3개 이상이면 각각 별도 파일로 쪼갤 후보
- 한 섹션 안에 서로 독립된 주제가 섞여 있으면 쪼개기
- "Related" / "References" 같은 부록이 비대해지면 별도 index 파일로

## 분리 전후 관계

- 분리된 새 파일들은 원본을 `relations` 에 유지
- 원본을 유지할 경우: 본문 상단에 "이 문서는 다음으로 분리되었습니다:" 섹션 추가
- 원본을 삭제하고 대체할 경우:
  - 원본을 deprecated 로 변경 후 일정 기간 유지 (참조 문서가 적응할 시간)
  - 또는 relations cleanup 을 거쳐 완전 삭제 (references/rule-relations.md 의 삭제 플로우)

## kb-validator 동작

- 필수 아님 (권장 항목)
- 초과 감지 시: 사용자에게 `"{path} 가 {N}줄입니다. 분리를 검토할까요?"` 확인
- "skip" 선택 시 해당 경고 이 세션에서 무시. 다음 실행 때 다시 감지

## 예외

아래 경우 경고 자체를 비활성화할 수 있다. 파일 frontmatter 에 태그 추가:

```yaml
tags: [..., length-exempt]
```

예외 태그가 있는 파일은 kb-validator 가 길이 경고에서 제외. 대신 해당 태그가 있으면 kb-validator 가 한 번은 "정말 예외 맞는지" 확인 후 더 이상 묻지 않는다.

## 왜 하드 리밋이 아닌가

- 도메인에 따라 정상 크기가 다르다 (용어집은 자연스럽게 길어짐)
- 강제 분리는 오히려 문맥 단절을 만든다
- 권장 + 알림 방식이 팀 문화에 적응하기 쉽다
